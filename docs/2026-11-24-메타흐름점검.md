# 메타 흐름 실시간 점검 (11/24 밤)

요청: "밤새 리얼타임으로 돌려 보고 고도화". 캐릭터별 영구 강화·세이브 버전 2·보스 패턴이 들어간
`claude/keen-fermi-kozt4p`(17e461b)를 `claude/unlocks`에 병합하고(fast-forward), 실제 브라우저로
런 → 결과 → 영구 강화 → 다음 런 흐름을 돌리며 고쳤다.

## 점검 도구: tools/metaflow.ts

```
npm run build:web
node tools/metaflow.ts --runs 6 --out <폴더>            # 데스크톱 1280×800
node tools/metaflow.ts --runs 4 --phone --out <폴더>    # Pixel 7 (412×915, 터치로 탭)
node tools/metaflow.ts --legacy --out <폴더>            # 예전 세이브만
```

- 웹 빌드를 호스트처럼 doctype을 붙여 http로 연다 (파일로 바로 열면 quirks 모드라 실제와 다르다).
- 주소 `#auto-rec-x8`: 판 안(카드·갈래·상점)만 봇이 하고, 메뉴는 도구가 **실제 버튼을 눌러** 지난다. 이 판은 기록·코인에 남는다
  (예전 `#auto`는 시험 판이라 기록에 남지 않았다).
- 한 판마다: 제목 → 시작 → 가장 최근에 열린 캐릭터 → 판 → 결과 → "<캐릭터> 영구 강화" → 가장 싼 노드부터 코인이 떨어질 때까지 구매 → 처음으로.
- 확인하는 것
  - 판 시작(스테이지 1, 0~1초) 능력치가 세이브의 그 캐릭터 트리로 `applyMeta`한 값과 같은지: 체력, 방어, 속도, 힘, 쿨다운, 범위, 연쇄 반경, 골드·줍기·회복·행운·조준 보조, 부활, 시작 골드 (`window.__pop.player`)
  - 결과 화면 "코인 +N"과 세이브 코인 증가가 같은지, "새로 열림"이 세이브의 새 해금과 같은지, 런 수 +1, 화면에 긴 소수가 없는지
  - 구매마다 가격만큼 코인이 줄었는지, 구매 뒤 스크롤이 튀지 않는지
  - 잠긴 캐릭터 카드가 꺼져 있는지
  - 두 판마다 새로고침: localStorage가 글자 하나 안 바뀌고 제목 화면 기록이 같은지
  - 예전 세이브(버전 1, 공용 트리 sturdy 2·strength 1·thrift 1, 큐 1판): 환불 안내 한 번(335코인), 코인 120 → 455, 트리 비움, 해금(올리·양치기·큐) 유지, 새로고침·영구 강화 화면에서 안내가 다시 안 뜸
- 판 안의 정비 상점·레벨업 화면도 한 번씩 찍는다. 1분마다 스테이지·시간·fps를 찍는다 (x8에서 60fps 유지).

## 영구 강화가 실제로 붙는지

- 9판 넘게 모든 판에서 시작 능력치가 트리대로였다 (위 "능력치 맞음"). 예: 데스크톱 2판 양치기는 1판에 올리가 산 공통 노드를 40% 싸게 샀고(초크 50 → 30), 다음 판 양치기에 붙었다. (양치기가 산 뒤 올리로 다시 한 판은 이 점검에 없다: "최근 캐릭터" 방식이라. 캐릭터별 적용은 단위 테스트가 본다.)
- 시작 골드(비상금)·부활 같은 특수 효과도 값이 맞았다.

## 해금 재확인 (tools/progress.ts --unlocks, 지금 조건: 양치기 스테이지 5, 큐 쿠션 250·3쿠션 30·6판, 팔레 적 30000)

12판, 색 공 규칙, 봇이 캐릭터별 트리를 산다. 숫자는 열린 판 번호.

| 방식 | 시드 | 양치기 | 큐 | 팔레 |
|---|---|---|---|---|
| 번갈아 | 1000~8000 | 2,1,2,2,1,1,1,2 | 모두 6 | 5,6,11,6,4,3,5,4 (중앙 5) |
| 최근 캐릭터 | 1000~4000 | 2,1,2,2 | 모두 6 | 7,8,9,10 |
| 예전 규칙 | 1000, 2000 | 6, 2 | 6, 6 | 9, 12 |

- 양치기 1~2판, 팔레 대개 4~10판으로 판마다 목표가 하나씩 있다.
- **큐는 봇에서 늘 6판 대체 조건으로 열린다.** 5판까지 쌓인 쿠션 팝이 60~240(3쿠션 0~11)이라 250·30에 못 미친다.
  사람이 쿠션을 노리면 앞당겨지는 지름길이라 그대로 두었지만, 쿠션 조건이 "실제로 여는 조건"이 되길 바라면 150~200으로 낮추는 것을 검토할 만하다 (메인 판단).
- 실제 브라우저 판에서도 같았다: 데스크톱 6판째 큐, 4판째 팔레(적 누적), 1판째 양치기.
